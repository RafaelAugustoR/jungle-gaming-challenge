# Issue #9 evidence

Wallet ledger pagination, reconciliation, and the authenticated console are covered through the approved HTTP, PostgreSQL, and browser seams.

## Verification

- `bun run build` — TypeScript typecheck and production frontend build passed.
- `INTEGRATION=1 bun test tests/integration/wallet-http.test.ts` — 11 tests passed against PostgreSQL and Keycloak. Covers exact values, operator/viewer access, a cursor retaining its first-page version ceiling while a new entry arrives, cursor binding to a wallet, and privileged disposable-database fixtures for a divergence and a reconstructed aggregate above the wallet input bound. Fixtures disable only the relevant integrity triggers and restore them; the API does not change discrepant balances. Tests check exact signed differences, log fields (`walletId`, `actorId`, `correlationId`, and entry count), and the Prometheus counter delta. The internal metrics scrape rejects unauthenticated access and allows the viewer role.
- `SCREENSHOTS=1 CHROME_PATH=/usr/bin/google-chrome bun run test:browser` — authenticated browser flow passed. The demo operator sees reconciliation results; viewer can read the wallet and ledger but has no reconciliation control. A held reconciliation response is released after selecting a second wallet and must not replace that wallet's view. This command builds host frontend assets before the test. The test adds the exact ephemeral callback URI to the existing Keycloak console client for its run and restores the prior redirect and origin arrays in teardown.
- Frontend taste lint reports the existing header/form dividers and form outline. Those baseline styles were preserved to keep the established console appearance.

## Ledger constraint evidence

- `tests/integration/wallet-chain.test.ts` verifies a processed transaction without a journal is rejected, and that version gaps, incorrect ledger arithmetic, and a wallet balance/version inconsistent with its journal are rejected.
- `tests/concurrency/bet.test.ts` verifies a second wallet completes while a different wallet is blocked on its PostgreSQL row lock, showing that shared counterpart accounts do not serialize independent wallets.
